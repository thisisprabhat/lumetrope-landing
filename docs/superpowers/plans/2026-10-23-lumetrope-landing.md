# Lumetrope Landing & Docs Site — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Task 0 copies this plan to `lumetrope_landing/docs/superpowers/plans/2026-10-23-lumetrope-landing.md`.

**Goal:** A fast, SEO/AEO-optimised marketing site plus a docs section for Lumetrope. Every section is driven by interactive dotLottie state machines rendered by Lumetrope's own engine, and the star is "Lumi", an original mascot.

**Architecture:** A static Vite + React + TS site, pre-rendered to real HTML per route (SSG via Vite SSR build plus a prerender script) and hydrated on the client.
- **Player:** Animations play in a small in-site player (`LumetropePlayer`) built on Lumetrope's WASM engine and its Canvas2D display-list renderer. Both are vendored from the Lumetrope repo by a sync script, so the site builds standalone without Rust.
- **Animations:** All `.lottie` files (with state machines) are generated by scripts that drive the engine's editing API, the same tool catalogue the MCP server exposes. They are reproducible, versioned and tested.
- **Media:** Playwright, using the installed Chrome, records real app footage and screenshots.

**Tech Stack:** Vite 5, React 18, TypeScript, Tailwind CSS (Lumetrope tokens), react-router (StaticRouter for SSG, BrowserRouter on the client), MDX (`@mdx-js/rollup`, remark-gfm, remark-frontmatter, rehype-slug), Vitest (+ @testing-library/react, jsdom), Playwright (`channel: "chrome"`), Lumetrope WASM engine (vendored), `@fontsource` (Instrument Sans/Serif, Martian Mono).

**Spec (from the request + decisions, 2026-10-23):**
- **Landing page:**
  - interactive animations that invite people to use the platform;
  - a screen recording and a screenshot carousel;
  - platform-specific downloads and the web app;
  - features (including MCP) and benefits.
- **Docs page:** how to use the app, platform installs, guides, the MCP guide, and more.
- **The whole site is interactive and built on dotLottie state machines.**
- **Mascot:** our own character "Lumi", built in Lumetrope and matching the darkroom theme (decision: own mascot, not third-party SVG).
- **Stack:** Vite + React + TS (decision) with a strong SEO **and AEO** focus.
- **Downloads:** GitHub Releases (decision).
- **Media:** recordings and screenshots scripted with Playwright (decision).

## Review Focus

1. **WASM unavailable** (old browser, blocked, wrong MIME): every section still reads fully, posters show and CTAs work. Test lives in Task 3 (`LottieStage` renders poster when `initEngine` rejects).
2. **No JS / crawlers:** the pre-rendered HTML has all copy, nav links, canonical, meta and valid JSON-LD. Test lives in Task 8 (prerender output assertions).
3. **Touch-only devices (no hover):** hover-driven states trigger on tap and focus, and pointer→composition mapping works for touch. Test lives in Task 3 (`toComp` and tap→`hover` input).
4. **Unknown or unusual platform** (Windows ARM, Linux distro, iPad, ChromeOS): the download section never shows a dead primary button; it falls back to "All downloads" plus the web app. Test lives in Task 6 (`primaryDownload` cases).
5. **Many players on one page:** offscreen players pause and don't run rAF, and there's one shared WASM init. Test lives in Task 3 (`IntersectionObserver` pause, init called once).

| Part | Definition |
|---|---|
| Segments | `idle 0–60` (breathe + blink loop), `lookL 60–75`, `lookR 75–90`, `wave 90–130`, `jump 130–160`, `cheer 160–210`, `sleep 210–270` |
| Inputs | `hover:Boolean`, `look:Numeric(-1..1)`, `sleepy:Boolean`, `poke:Event`, `cheer:Event` |
| States | `Idle` (initial, loop), `LookLeft`, `LookRight`, `Wave` (loop), `Jump` (once), `Cheer` (once), `Sleep` (loop) |
| Global state | `poke` → `Jump`; `cheer` → `Cheer` |

Lumi's transitions:
- `Idle`→`Wave` when `hover==true`; `Wave`→`Idle` when `hover==false`
- `Idle`→`LookLeft` when `look<-0.33`; `Idle`→`LookRight` when `look>0.33`; both back to `Idle` when `-0.33≤look≤0.33`
- `Idle`→`Sleep` when `sleepy==true`; `Sleep`→`Idle` when `sleepy==false` (tweened 0.3 s)
- `Jump` and `Cheer` → `Idle` on complete (no guard)

Lumi's interactions: `Click` on layer `Body` fires `poke`; `PointerEnter` and `PointerExit` on `Body` set `hover`.

Per-feature **Icon**: input `hover:Boolean`; states `Rest` (subtle loop) ⇄ `Active` (tweened 0.2 s); interaction `PointerEnter`/`PointerExit` sets `hover`.

**Zoetrope** (benefits): input `progress:Numeric(0..1)` driven by scroll; states `B1..B4` gated by `progress` thresholds `0.25/0.5/0.75`; `Click` fires `spin:Event` → `Spin` (once) → back.

**Cta**: inputs `hover:Boolean`, `press:Event`, `done:Event`; states `Rest`, `Hover`, `Pressed`, `Done` (check mark, once → `Rest`).

**Logo**: spinning disc that speeds up on hover.

**Explainer**: the toggle demo used in the state-machine docs.

- the player class:

```ts
class LumetropePlayer {
  static create(canvas: HTMLCanvasElement, o: { src: string; stateMachine?: string; fit?: "contain"|"cover"; onState?: (s: string) => void }): Promise<LumetropePlayer>;
  setInput(name: string, v: boolean|number|string): void;
  fire(name: string): void;
  pointer(kind: "move"|"down"|"up"|"click"|"enter"|"exit", clientX: number, clientY: number): void;
  play(): void; pause(): void; resize(): void; destroy(): void;
  readonly state: string | null;
}
```

- `<LottieStage src stateMachine poster alt fit className onState inputs? ref>`; the ref exposes `{ setInput, fire }`.
- `bus`: `emit(name, data?)`, `on(name, cb) → off`.

Player behaviour:
- **Rendering:** a rAF loop with `sm_tick(dt)` → `display_list(frame, scale·dpr, x·dpr, y·dpr)` → `CanvasRenderer.render`, at DPR resolution.
- **Pointer:** pointer events map through `toComp`; tap (`pointerdown` with `pointerType` touch) also sets `hover=true` for 1.2 s.
- **Keyboard:** focusable (`tabIndex=0`); `focus`/`blur` set `hover`; Enter/Space fire `click`.
- **Visibility:** `IntersectionObserver` pauses offscreen players; `document.hidden` pauses all.
- **Reduced motion:** the poster stays until a click.
- **Failure:** if `initEngine` rejects, the poster stays (Review Focus 1).
